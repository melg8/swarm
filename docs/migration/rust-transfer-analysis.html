Anatomy of the actual codebase

What would actually be ported

swarm is a headless Lineage 2 client that speaks the game wire protocol directly, plays characters autonomously (fight, loot, shop, pathfind, delevel), renders a live fleet web UI, and can proxy a real game client. 4831 tracked files, of which 396 are Go sources. Crucially, 62,438 lines of the biggest package (npcdata) are machine-generated data tables — the genuine hand-written logic is ≈ 68k LOC.

Source LOC by package (non-test)

Code composition

  • 0 cgo, 0 C dependencies — nothing blocks a port mechanically.
  • 7 interface declarations in 130k LOC — concrete, data-oriented style; traits map 1:1.
  • 12 unsafe uses, all little-endian wire casts → become safe from_le_bytes in Rust.
  • Test/code ratio 0.38 with 197 test files — the migration safety net already exists.
  • Repo constitution AGENTS.md: “no Rust, no Node, no C” and “learn Go” is a stated goal.
The single best port asset: the entire test suite runs offline without the game server (measured: 24/24 packages ok, ~200 s). Packet fixtures, geodata and hunt-loop repro tests form a complete behavioral specification a Rust rewrite could be validated against.

Experiment 3 · the compile loop an agent lives inside

The developer loop: Go's killer advantage

An AI agent pays the compile-test-fix cycle hundreds of times per day. Each second of latency and each dependency in the tree is multiplied across every change. Measured cold and warm, on this 2-core machine.

Build & feedback latency

  • Real swarm project (130k LOC): clean 21.6 s, incremental rebuild after a one-line touch 0.57 s, full binary.
  • A same-scale Rust project would pay warm cargo check in seconds and full --release builds in minutes on this hardware.
  • Agents do build → read → patch loops 50–200× per session: latency compounds.

In Rust, 151 transitive crates multiply the API-recall burden (axum 0.7 vs 0.8 breakage is the canonical agent trap).

The agent lens · first-hand + measured

How each language treats an AI developer

Development here is agent-only, so the developer experience that matters is the model experience: iteration latency, context economics, API recall, and how the compiler partners with the agent. Measured this session, plus one honest anecdote: the Go benchmark binary compiled on the first attempt; the Rust twin needed 3 fix-compile rounds (async fn placement, tokio's recv returning Option where std returns Result, cascading E0308s).

Field notes from this session

  • Iteration latency compounds. 0.09–0.6 s Go rebuilds vs 0.3 s checks / 6+ s Rust binaries. An agent runs this loop hundreds of times a day.
  • Context is the scarce resource. 62 B/error vs 421 B/error (measured). On multi-error refactors, rustc output floods the window and triggers summarization loss.
  • Go's uniformity is recall-friendly. Stdlib-shaped code (this repo: 4 deps) matches the corpus almost perfectly; 151-crate Rust stacks multiply version-churn traps (axum 0.6→0.7→0.8).
  • Rust repays the tax with guarantees. Data races become compile errors, match on packet opcodes is exhaustively checked, no nil dereference class, wire casts become safe from_le_bytes.
  • Net for agent-only development: Go optimizes the mean (throughput of verified changes); Rust optimizes the tail (defect classes that cannot ship). Swarm's economics are mean-driven.

Scope: ~68k hand-written LOC + 49.3k test LOC to re-express at a 1.1–1.3× Rust ratio → roughly 75–90k lines of new Rust. The hunt loop is the risk core: 25.8k LOC of emergent, interleaved behavior whose repro tests encode hundreds of discovered edge cases.

Balance sheet

Pros and cons, honestly weighed

What the transfer would buy

  • Data-race-free concurrency by construction — the 208 lock sites and 88 selects become compile-verified; miri checks the unsafe remnants.
  • 4× JSON throughput, 21% HTTP throughput, 6.7× task-memory efficiency (all measured) — headroom for a thousand-bot fleet.
  • Exhaustive packet dispatch — every opcode switch becomes a total match; adding a packet breaks compilation until handled everywhere.
  • The unsafe layer ends safer — 12 Go unsafe.Pointer casts become plain safe from_le_bytes.
  • Clippy > golangci in depth; cargo-audit/deny give stronger supply-chain gates; rustfmt removes the need for the repo's home-grown formatter.
  • Static musl binaries, FFI/cdylib and WASM doors open — Go can do most of this, with more friction.

What it would cost

  • ~18 weeks of port + hardening against a workload that both languages already overshoot by 4 orders of magnitude.
  • 10–100× worse agent iteration economics — slower loops (measured 0.09 vs 6.3 s) and 4.5–6.8× the diagnostic context per error (measured).
  • 151-crate API-recall surface for agents instead of 5 Go modules — more hallucination traps, more version churn (axum majors in 3 years: 0.6→0.8).
  • Constitutional violation — AGENTS.md forbids Rust and states "learn Go on unforgiving requirements" as a project goal; 251 docs are Go-shaped.
  • Hunt-loop regression risk — 25.8k LOC of emergent behavior with 17.2k LOC of hard-won repro tests to re-earn.
  • Async re-architecture — context.Context cancellation (84 uses) has no drop-equivalent; every session loop is hand-audited for cancellation.
  • GC pauses are a non-issue here — Go's sub-millisecond GC at this allocation profile never appears in the p99 of a bot tick.
12 / 12
Final verdict

Stay on Go. Write the triggers down. Move on.

The transfer is feasible but unjustified: full ecosystem coverage and a test suite that could steer a rewrite — against a performance argument that does not exist at this scale, an agent-economics argument that strongly favors Go, and a project constitution that chose Go on purpose. The rational move is to keep the analysis, define the tripwires, and spend the next 18 weeks on the roadmap instead.

Revisit Rust when…

  • Fleet target ≥ 1,000 bots per process (task-memory argument activates)
  • A profiled CPU hot spot survives optimization attempts (pathfind at scale is the candidate)
  • Product needs FFI embedding, WASM, or musl-static distribution
  • The race detector ever misses a production race — Rust makes the class unrepresentable

If a trigger fires

  • Hybrid first: extract the hot module as a sidecar crate — not a big-bang rewrite
  • Port packets + crypt first (fixture-rich, mechanically verifiable)
  • Keep the Go suite as the oracle: differential-test old vs new on live traffic
  • Retarget the npcdata generator, never hand-port 62k generated lines
